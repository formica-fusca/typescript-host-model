## The word "host"

A **host** is whatever will load and run the emitted JavaScript. Concretely it is
three things bundled together:

1. a **syntax level** — what the parser accepts (`?.`, `#private`, top-level
   `await`);
2. a **standard library** — what already exists at runtime (`Map`,
   `Array.prototype.findLast`, `structuredClone`, `document`);
3. a **module system** — how a file declares its imports, and how a specifier
   string is turned into a file on disk.

Node 24 is a host. Chrome 141 is a host. A Cloudflare Worker is a host. A bundler
is a _pretend_ host: it resolves and links like one, then hands the result to a
real one — which is why a project can have two hosts disagreeing about the same
source tree.

TypeScript never inspects the host. It cannot: the host is not present at compile
time, it may be several different hosts, and it may not exist yet. So the
compiler works from a **description** you supply, and these four options are that
description — one for the syntax level, one for the standard library, and two for
the module system.

Nothing verifies the description. That single fact generates every failure this
course is about.

> **A collision worth defusing now.** TypeScript's own API uses "Host" for the
> opposite thing. `CompilerHost`, `ModuleResolutionHost` and `LanguageServiceHost`
> are interfaces of `fileExists` / `readFile` — they describe the environment the
> **compiler itself** runs in, the thing that hands `tsc` bytes off a disk. That
> host is where compilation _happens_; ours is where the output _ends up_. The
> course always means the second one, and says "compiler host" in full on the rare
> occasions it means the first.

## General objective

By the end you can read those four lines in a `tsconfig.json` you have never seen
and predict, without running anything: **what syntax will be emitted, which
globals will typecheck, what module format each file receives, and which file a
given specifier resolves to.**

And in reverse — the half that pays off during an incident. Given a symptom, you
can name which option described a host that does not exist:

| Symptom                                                                | Which claim was false                                                               |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `x.findLast is not a function`, compiled clean                         | `lib` promised a standard library the runtime does not have                         |
| `Cannot find name 'document'` — or worse, _no_ error in a Node service | `lib`, via a default nobody set                                                     |
| `ERR_MODULE_NOT_FOUND` after a green build                             | `moduleResolution` modelled a different file-lookup algorithm than the runtime uses |
| `Unexpected token` in a consumer's build                               | `target` emitted syntax the consumer's host cannot parse                            |

The secondary objective is a habit rather than a fact: **check the value list
against the compiler in front of you.** Two of these four options have had values
_removed_ recently — `es5` is no longer a legal `target`, and `node10` is no
longer a legal `moduleResolution` — which quietly invalidates most published
advice on the subject, including advice that is otherwise correct.
